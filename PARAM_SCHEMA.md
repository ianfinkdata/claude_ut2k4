# Procedural Generator Parameter Schema

Derived from analysis of all 39 stock UT2004 DM maps via `navanalysis.py`.
These are the tunable knobs for a procedural map generator, grounded in the
measured invariants of the official map set.

---

## How to read this document

Each parameter lists:
- **Range** — min / median / max observed across 39 maps
- **Generator default** — recommended starting value for a "stock-feeling" map
- **Notes** — design rationale or constraints

All distance values are in Unreal Units (uu). 1uu ≈ 1 inch; a human player
is ~96uu tall; a typical room height is 256–512uu.

---

## Scale parameters

### `nav_node_count` — total navigation nodes
| Stat | Value |
|---|---|
| Min | 63 (DM-Insidious, tight 1v1) |
| Median | 183 |
| Max | 391 (DM-Phobos2, large multi-arena) |
| **Default** | **150** (medium-small, good for 4–8 player FFA) |

Includes PathNode + InventorySpot + PlayerStart + LiftCenter + LiftExit +
JumpSpot. `InventorySpot` count is not a free parameter — it's always 1:1 with
pickups (see `pickup_total` below). Effective free node count =
`nav_node_count - pickup_total - playerstarts - lift_nodes`.

### `nav_area` — map footprint (sq uu, bounding box of nav nodes)
| Stat | Value |
|---|---|
| Min | 4.1M sq uu (DM-1on1-Serpentine) |
| Median | 18.8M sq uu |
| Max | 93.8M sq uu (DM-DesertIsle) |
| **Default** | **16M sq uu** (~4000×4000uu room footprint) |

Use as a density constraint: `nav_node_count / nav_area` should stay near the
stock average (~10 nodes per million sq uu).

## Connectivity parameters

### `avg_out_degree` — average nav-node out-degree
| Stat | Value |
|---|---|
| Min | 3.35 |
| Median | 4.13 |
| Max | 5.04 |
| Stdev | 0.39 (tight — strong design rule) |
| **Default** | **4.0** |

Target: place PathNodes close enough that each ends up with ~4 reachable
neighbours after Build AI Paths. Deviation much below 3 means isolated nodes;
much above 5 means the layout is too open (few walls/obstacles).

### `walk_gap_max` — maximum distance between two walk-connected nav nodes
| Stat | Value |
|---|---|
| Hard ceiling across all 39 maps | **1199 uu** |
| Per-map median walk gap | 390 uu (median across maps) |
| Walk edges over 1200 uu | **0 / 30,888 (0%)** |
| **Generator rule** | **No walk gap > 1200 uu** |

This is the single hardest constraint in the data: every stock map keeps all
walk-only edges under 1200uu. Violating this creates unreachable/stranded
nodes after Build AI Paths. Generator must ensure PathNode density keeps the
maximum inter-node walk distance below this ceiling.

### `jump_edge_fraction` — fraction of edges flagged R_JUMP
| Stat | Value |
|---|---|
| Min | 0.4% (DM-Insidious, ground-only) |
| Median | 14.1% |
| Max | 47% (DM-1on1-Serpentine, jump-centric) |
| **Default** | **14%** |

Controlled by map geometry (ledges, gaps, platform heights). A jump-edge is
generated by Build AI Paths when a height difference or horizontal gap exists
that requires a jump. The generator can tune this by adding/removing elevated
platforms and ledges.

### `forced_edge_fraction` — fraction of edges flagged bForced (jump pads, one-way)
| Stat | Value |
|---|---|
| Min | 0% (5 maps) |
| Median | 1.5% |
| Max | 5.2% (DM-Plunge, jump-pad intensive) |
| **Default** | **0%** (omit jump pads in first-pass generator) |

## Spawn parameters

### `playerstarts` — PlayerStart actor count
| Stat | Value |
|---|---|
| Min | 6 (DM-1on1-Trite) |
| Median | 16 |
| Max | 32 (DM-DE-Grendelkeep) |
| **Default** | **16** |

Strong clustering at 16 — this is the design standard for FFA DM. 1v1 maps
use 6–8. PlayerStarts must be spread across the map; no two within ~500uu of
each other for bot safety.

## Pickup / item economy parameters

### `pickup_total` — total pickup count
| Stat | Value |
|---|---|
| Min | 17 (DM-Gael) |
| Median | 54 |
| Max | 122 (DM-DE-Grendelkeep) |
| **Default** | **40** (medium density) |

Each pickup requires exactly one `InventorySpot` node (the 1:1 anchoring rule,
confirmed: ratio = 1.003 across all 39 maps). `InventorySpot` count is always
equal to `pickup_total`.

### Pickup category mix (fraction of `pickup_total`)

| Category | Global fraction | Per-map median count | **Generator default fraction** |
|---|---|---|---|
| Ammo | 36.5% | 18 | **36%** |
| Health | 28.4% | 17 | **28%** |
| Adrenaline | 16.8% | 10 | **17%** |
| Weapon | 14.1% | 7 | **14%** |
| Armor | 2.9% | 2 | **3%** |
| Powerup | 1.3% | 1 | **2%** (0 or 1 per map) |

Notes:
- 11/39 maps have zero adrenaline pickups (optional).
- 16/39 maps have zero powerups (optional; UDamage/SuperShield are high-value,
  place at most 1–2, at exposed/contested locations).
- Weapon count (median 7) closely matches the number of distinct weapon types
  in a typical FFA loadout; don't exceed ~14.

## Verticality parameters

### `z_range` — vertical extent of nav nodes (max Z - min Z)
| Stat | Value |
|---|---|
| Min | 320 uu (near-flat map) |
| Median | 941 uu |
| Max | 3712 uu (multi-floor tower maps) |
| **Default** | **512 uu** (one main floor + one elevated area) |

### `floor_count` — distinct 256uu Z-bands occupied by nav nodes
| Stat | Value |
|---|---|
| Min | 2 |
| Median | 4 |
| Max | 14 |
| **Default** | **3** (ground + mid-level + upper) |

A "floor" here is a 256uu Z-bucket — coarse but sufficient for generator
planning. Each floor needs its own PathNode coverage; jump/lift edges connect
them.

---

## Lift parameters (relevant once multi-floor layouts are in scope)

### `lift_count` — number of lifts (LiftCenter actors)
| Stat | Value |
|---|---|
| Maps with lifts | 31/39 (79%) |
| Min | 0 |
| Median | 2 |
| Max | 6 |
| **Default** | **0** (first-pass generator; add lifts in v2) |

### `avg_lift_height` — average vertical span per lift (uu)
| Stat | Value |
|---|---|
| Median across maps | 416 uu (~1.6 floors at 256uu/floor) |
| Max observed | 1152 uu |
| **Default** | **384 uu** |

Each lift needs one `LiftCenter` at the base and one or more `LiftExit` nodes
at each landing, all sharing the same `LiftTag`. Walk/forced edges connect the
lift to surrounding PathNodes on each floor.

## Recommended first-pass generator targets (MVP)

A single-room map targeting the "minimal" end of the stock range:

```
nav_node_count:    ~40   (room + a few path nodes)
playerstarts:       8
pickup_total:      20    (ammo=8, health=6, adrenaline=3, weapon=3)
avg_out_degree:     4.0
walk_gap_max:    <1200   (HARD CONSTRAINT)
floor_count:        1    (one flat room)
lift_count:         0
jump_edge_fraction: 5%   (low — minimal geometry)
z_range:          256    (single floor)
```

This is essentially what `gen_testmap.py` already produces (Step 9). The next
step is extending the generator to compose multi-room layouts while keeping
`walk_gap_max < 1200` satisfied everywhere.
