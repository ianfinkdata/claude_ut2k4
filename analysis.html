The pipeline

The architecture is read binary, write text, finalize in-engine — never hand-author the fragile binary format. We decode the package directly, emit UnrealEd's plain-text T3D format, and let the engine do the hard serialization.

Binary .ut2→ Python decode→ Generate T3D→ UnrealEd Import + Build→ Saved .ut2

Everything that parses cleanly: header, name/import/export tables, the full per-actor property set, and — the part the format docs call "not fully public" — the brush/BSP geometry, decoded from the binary Model → Polys → FPoly chain to blocks that are byte-identical to the engine's own export.

What did we have to leave out?

To make a new map saveable, our generator omits references that would otherwise bind to the original package's private objects. We logged 4,104 such omissions — and the punchline is that the engine rebuilds every single one on Build All:

OmittedCountFate
Region (zone bindings)1,949recomputed on Build Geometry
ReachSpec (bot-path edges)909rebuilt by Build AI Paths
StaticMeshInstance (lighting cache)680rebuilt on Build Lighting
Brush→Model bindings554rewritten to local geometry
ConvexVolume (antiportals)10rebuilt on Build Geometry
Level metadata (cosmetic)2the only non-regenerated items

Of 4,104 omissions, exactly two aren't auto-rebuilt — and neither lives in the playable world.

Both sit on the map's settings object: the menu loading thumbnail and the map-info card (title, author, recommended players). Cosmetic, menu-only metadata. That is the entire visible difference between the replica and the original — which is why it plays, looks, and navigates exactly the same.

Repeatable sub-structures

The patterns are concrete enough to procedurally stamp out:

  • Pickup anchoring — drop the item, drop one InventorySpot at its base, wire it into the nearby graph.
  • PathNode mesh — nodes at junctions and along runs so no walkable gap exceeds ~1,200 units; the engine fills in the edges.
  • Jump links — JumpSpot nodes joined by jump edges, often "forced" for jump-pad boosts.
  • Lift template — a Mover + one LiftCenter on the platform + a LiftExit per floor, all tied by a shared LiftTag, with bidirectional special edges connecting center ↔ exits.

The kicker: when we replicated Rankin, Build AI Paths regenerated the original's exact 891-edge bot graph from nothing but node placement. The patterns above aren't just observations — they're the generative recipe, and the engine proved it live.
