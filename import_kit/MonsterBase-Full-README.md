# MonsterBase-Full.t3d — multi-room "Deathmatch in a monster base"

Generated by `gen_monsterbase.py` + `apply_palette.py` (tech-rankin). The full-map
expansion of the funtested single-room gate (`claude_test_monster_spike.ut2`).

## Layout

A central **hub arena** (8 PlayerStarts, basic weapons — the DM space) with **3
escalating gated branches**. Each branch reuses the proven gate pattern:

```
HUB ──open doorway──▶ ANTECHAMBER (guardians, fightable) ──gated door──▶ VAULT (reward)
```

| Branch | Guardians | Reward (vault) | Extras |
|---|---|---|---|
| **North** | 2 × Gasbag | FlakCannon | flak ammo, health |
| **East** | 3 × Skaarj | RocketLauncher | rocket ammo, ShieldPack |
| **West** | **5 × Warlord** | **Redeemer** (the one and only) | rocket ammo, ShieldPack |

Guardians stand in the open antechamber (reachable from the hub, fightable with
hub weapons). Clearing a branch's guardians trips its `Counter`, opening the
static-mesh `Mover` door to that branch's reward vault. Same-species packs per
gate (the infighting rule from `MONSTER_GATING.md` §1.1b).

97 actors, 13 brushes (all subtract; walls are uncarved solid), 16 pickups each
with a 1:1 InventorySpot, 17 PathNodes (worst gap 416uu << 1200), flat single
floor (Z 0–384).

## Doors — IMPORTANT (map-local mesh)

Doors follow your **Mover0 template**: a `DT_StaticMesh` Mover, tag-triggered
(`TriggerOpenTimed`), latching open. But your Mover0's mesh is **map-local**
(`claude_test_monster_spike.movers.Door`) and will NOT resolve in a fresh level,
so this build defaults the door mesh to a resolvable shared one:
`HumanoidHardware.Miscellaneous.MDoor01HA`.

- Building this as a **standalone** map → keep the default (resolves cleanly).
- Building it **inside the committed package** (where `movers.Door` exists) →
  regenerate with your mesh:
  ```bash
  python gen_monsterbase.py --door-mesh "claude_test_monster_spike.movers.Door" -o _raw.t3d
  python apply_palette.py _raw.t3d palettes/tech-rankin.json -o import_kit/MonsterBase-Full.t3d
  ```
Door `DrawScale3D`/`Rotation` are a first cut — expect to nudge scale in-editor so
each door fills its 192×256uu opening (mesh dimensions vary).

## Monster respawn

Resolved (see `MONSTER_RESPAWN.md`): a map-only timed monster respawn is **not
cleanly possible** — there's no stock placeable pawn spawner, and the `Counter`
latches permanently (no mid-match reset), so a gate cannot re-arm without a
mutator. **Gates are therefore one-shot by design.** The reward still re-arms on a
timer for free: the **Redeemer self-respawns every 120s** (flat, no difficulty
scaling), so the West vault keeps refilling after it's first cleared. True
guardian respawn would require the small mutator (breaks the no-code constraint).

## Build / test

Paste into a blank UnrealEd level → Build Geometry → Build Lighting → Build AI
Paths → Play. Requires stock packages: `HumanoidArchitecture.utx`,
`HumanoidHardware.usx` (door), `SkaarjPack`, `XWeapons`, `XPickups`, `GamePlay`.
Not yet validated in-engine — this is the human build + funtest pass.
